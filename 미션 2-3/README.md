## 진행 순서

1. v1 HTML을 브라우저에서 열고 이전 테스트를 재현한다. 예상과 다른 결과가 있으면 우선 수정 대상으로 정한다.
2. 테스트 내용·입력값·예상 결과·실제 결과를 기록한다. 확인하지 않은 원인을 단정하지 않는다.
3. 문제를 AI에게 설명하여 한 번에 하나씩 수정하고, 전체 HTML을 `숨은보험금찾기v2.html`, `숨은보험금찾기v3.html`처럼 별도로 저장한다.
4. 수정한 기능을 같은 조건으로 다시 시험하고, 이전에 정상 동작한 기능도 함께 확인한다. 수정 기록을 3건 작성한다.
5. 대상 사용자 또는 동료 1명에게 사용법 설명 없이 수행할 작업만 제시하고 행동·질문·피드백을 관찰한다.
6. 피드백 중 1건 이상을 반영하고 결과를 다시 테스트한다.
7. 최종 HTML에 맞게 기획서와 제작검증기록을 정리하고 최종 제출물 3개를 확인한다.

## 수정 기록 3건의 필수 항목

각 수정 건에 다음 내용을 남긴다.

- **발견한 문제:** 테스트 내용·예상 결과·실제 결과
- **AI에게 전달한 요청**
- **수정 후 테스트 결과:** 같은 조건의 재시험과 기존 정상 기능 확인
- **수정 이유:** 해결하지 않았을 때 사용자가 겪을 불편

변경 전후 HTML과 캡처를 구분하여 보관한다. AI의 지적은 직접 재현한 뒤 반영 여부를 결정한다.

## 사용자 테스트의 필수 항목

- **테스트 참여자와 요청한 작업**
- **사용자의 행동과 질문**
- **받은 피드백**
- **반영 내용과 결과**

관찰하지 않은 행동이나 발언은 작성하지 않는다. 사용자가 어려움을 겪지 않았다면 그대로 기록한다. 실제 참여자 테스트와 피드백 반영은 아직 수행하지 않았다.

## 최종 기획서 확인

- 변경된 화면 구성·동작·완료 기준을 반영한다.
- 구현하지 않은 기능은 추가 기능으로 분류한다.
- 한계 및 비목표 3가지와 검증 방법 1가지가 최종 HTML에 맞는지 확인한다.

## 구현·제출 조건

- HTML은 CSS와 필요한 JavaScript를 포함한 파일 1개로 구성한다.
- 평가자가 브라우저에서 열어 기획서의 필수 기능을 확인할 수 있어야 한다.
- 로그인·API 키·서버가 필요한 기능 및 챗봇·AI 기능은 추가 기능으로 분류한다. 해당 기능 없이도 페이지가 열리고 동작해야 한다.
