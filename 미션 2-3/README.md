# 미션 2-3: 테스트와 사용자 피드백 반영

미션 2-2에서 선택한 HTML을 테스트하고 수정한 뒤, 사용자 1명의 피드백을 반영한다. 최종 HTML에 맞춰 기획서와 제작검증기록을 정리한다.

## 먼저 확인할 내용

- 저장소에 등록된 HTML은 **v2, v3, v3-1**이다.
- **v4, v4-1, v5, v5_1, v5_2의 예시 없는 공개용 사본**을 [공개용사본](./공개용사본/)에 ZIP으로 등록했다. 각 ZIP에는 HTML 파일 한 개가 들어 있다. 원본은 변경하지 않았다.
- 최종 제출 버전은 아직 확정하지 않았다. **수정·재시험 3건과 사용자 테스트 완료를 의미하지 않는다.**
- 기존 HTML과 캡처는 내용·파일명을 바꾸지 않고 보존했다. 상세 기록은 [버전별 수정 기록](./작업기록/버전별수정기록.md)에 모았다.

## 실행과 대용량 파일 관리

1. GitHub의 HTML 파일 페이지는 소스 보기 화면이다. 파일 화면에서 **Download raw file**로 내려받은 뒤 브라우저에서 연다.
2. 공개용 HTML은 약 39~41 MB이며 다운로드 ZIP은 약 10~12 MB다. 압축만 했으므로 풀었을 때 HTML 크기는 다시 커진다. 브라우저 업로드는 파일당 25 MiB까지이며 Git 전송의 파일 제한은 100 MiB다. [GitHub 공식 크기 안내](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)
3. 폴더 이동만으로 원본 파일 용량은 줄지 않는다. 크기를 줄이려면 내장 자료를 확인해야 하며, 원본 보존과 동작 검증 없이 내용을 삭제하거나 나누지 않는다.
4. 공개용 사본에서는 개인 증권·약관 참조 링크, 보험 샘플 관찰자료, 데모 보험카드·금액을 제거했다. 가상 자료도 넣지 않았다. 개인 원본은 공개용 사본과 별도로 보관한다.
5. 제출 조건은 CSS와 필요한 JavaScript를 포함한 **HTML 파일 한 개**다. 정리를 위해 여러 파일로 나눌 경우에도 최종 제출 조건을 유지해야 한다.
