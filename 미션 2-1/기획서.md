# 숨은 보험금 찾기 — 개인용 보험 보장 검색·예상금액 계산 페이지

> 작성일: 2026-11-07  
> 작성 상태: 사용자와의 질문·답변을 반영한 제작 전 기획  
> 구현 목표: 로그인·API 키·서버·챗봇·AI 없이 실행하는 **HTML 파일 1개**  
> 사용 환경: 컴퓨터와 아이폰·안드로이드의 브라우저  
> 이번 버전의 입력 원칙: **이름·주민등록번호·연락처·전체 증권번호 등 개인정보는 입력하지 않음**. 공개 약관과 개인정보를 제거한 보장 조건·가입금액을 사용해 계산 결과를 검증한다.  
> 주의: 이 문서는 구현 결과나 보험금 지급을 보증하지 않는다. 완료 여부는 아래 기준으로 직접 검증한다.

## 대상 사용자

- **사용자:** 본인 1명. 다른 사람의 계정이나 가족별 프로필은 현재 만들지 않는다.
- **사용 기기:** 컴퓨터와 스마트폰(아이폰·안드로이드)에서 모든 주요 기능을 사용한다.
- **사용 방식:** 개인이 가지고 있는 보험증권·약관·계약서·병원 서류를 확인하고, 자신에게 해당할 가능성이 있는 보장 항목을 찾는다.
- **접근 방식:** 회원가입·로그인 없이 HTML 파일 하나를 일반 창과 시크릿/개인정보 보호 창에서 직접 열어 사용한다. 브라우저·기기마다 저장 공간이 별개이므로 자료 이동은 백업 파일로 직접 수행한다.

## 사용 목적

1. 질병명·상해명 또는 진단코드 **한 개를 입력**하여, 미리 등록한 **약관부터 검색**하고 관련 보장을 찾는다.
2. 검색된 약관의 조건을 실제 가입한 **보험증권·상품·특약**과 대조한 뒤, 진단일·계약 기간·수술·입원·지급 횟수·한도 등을 확인한다.
3. 사용자가 **개인정보를 제외한 실제 가입금액·특약별 지급 조건·진단/치료 사실**과 확인란을 직접 채우면 **지급가능금액**, **예상금액**, **정보 부족/추가 확인**을 구분하고 보험회사·상품·특약별 **원 단위 계산액·계산식·각각의 합계**를 보여 준다. 실제로 청구해 확정된 수령액을 보증하는 것은 아니다.
4. 아직 청구하지 않았을 **가능성이 있는 항목**을 사용자가 표시해 다시 볼 수 있도록 한다. 실제 미청구 여부나 보험사의 최종 지급 여부를 자동으로 판정하지는 않는다.
5. 개인정보를 마스킹한 보험 서류는 **검색 가능한 변환 데이터**를 중심으로 브라우저에 저장하고, 용량이 큰 PDF는 필요할 때 직접 불러와 확인한다. 태그·확인 기록의 자동 저장, 백업·복원, PDF/CSV 내보내기는 유지한다.
6. 검색 범위는 등록된 보험의 **진단비·수술비·입원일당·실손의료비·통원비·치료비·후유장해·간병·운전자·여행 관련 특약 등 전체 보장 항목**으로 하되, 조건이 없어 계산할 수 없는 항목은 임의로 금액을 만들지 않는다.

## 화면 구성과 동작

### 1. 첫 화면 — 내 보험 현황과 최근 검색

- 등록된 보험회사·상품·특약·문서 수를 보여 준다.
- 질병명 또는 진단코드를 입력하는 검색창과 **[검색]**, **[테스트용 초기화]**, **[보험 자료 등록]**, **[백업]**, **[복원]** 버튼을 둔다.
- 최근 검색한 질병과 해당 검색 시점의 지급가능금액·예상금액, 검토가 필요한 항목 수, 마지막 백업 날짜를 표시한다. 검색하지 않은 상태에서 모든 보험의 가입금액을 실제 받을 돈처럼 합산하지 않는다.
- 처음 열면 실제 보험 정보는 비어 있으며, 실제 데이터와 섞이지 않는 **[체험용 자료]** 버튼을 별도로 둔다. 체험 모드는 가상 금액·조건으로 검색과 계산을 연습한다. **체험 기록은 브라우저에 자동 저장하지 않지만 [가상 테스트 저장]으로 별도 파일에 보관**할 수 있다. 체험 종료·재시작 시 **검색어와 검색 결과가 없는 초기 검색 상태**로 돌아가고, 필요하면 **[가상 테스트 불러오기]**로 저장했던 상태를 다시 연다. 일반/시크릿 창 모두 동일하게 동작한다.

**첫 화면의 데이터 표시 규칙**

1. 자료가 등록되지 않았으면 결과 영역에 `등록된 보험 자료가 없습니다. 보험 자료를 등록하거나 가상 체험을 시작하세요.`를 보여 주고 실제 금액을 임의로 표시하지 않는다.
2. 검색 전에는 `검색하면 관련 보장이 여기에 표시됩니다.`를 보여 주며 관련 보장 건수·지급가능 추정액·예상금액은 **`—`**로 표시한다. `0원`은 실제 검색·계산 결과가 0원인 경우에만 사용한다.
3. 검색 후에는 약관 검색 → 보험증권·특약 확인 → 지급 조건 확인 순서를 유지한다. `조건 확인` 또는 `자료 부족` 카드에 **지급가능 확정액처럼 보이는 숫자**를 표시하지 않는다. 금액을 계산할 근거가 부족한 카드는 `금액 산정 불가`를 표시한다.
4. 오른쪽 패널의 막대 비교 그림을 사용하는 경우 실제 계산된 범주와 값만 그리며, 불명확한 `최소 추정`이나 시안의 예시 금액을 실제 결과처럼 반복해서 보여 주지 않는다.

#### **[테스트용 초기화] 버튼 명세 — 검색 결과만 초기화**

- **위치·이름:** 상단 검색 영역의 **[검색]** 옆에 보조 버튼 **[테스트용 초기화]**를 둔다. 옆에 `검색 결과만 지워집니다`라는 설명을 표시한다. 일반 검색과 가상 체험 검색 모두에서 사용할 수 있다.
- **누르면 사라지는 것:** **현재 화면에 표시된 검색 결과 카드, 결과 건수, 현재 검색으로 계산해 표시한 지급가능 추정액·예상금액·추가 확인 건수, 관련 그래프**만 비운다. 결과 영역은 검색 전 안내 문구로 돌아간다.
- **남아 있는 것:** 사용자가 입력한 **검색어와 선택한 태그**, 등록한 **보험약관·증권·변환 JSON·가입금액·문서 연결·태그**, 기존 **검색 기록**, 체크·메모·수정 이력·저장된 가상 JSON 문서는 **그대로 유지**한다. 브라우저 자동 저장 데이터도 삭제하지 않는다.
- **다시 검색:** 검색어와 태그를 유지한 상태에서 **[검색]**을 누르면 저장된 자료와 조건을 다시 조회·계산해 결과를 표시한다. 초기화 버튼을 누르는 것만으로 새 검색 기록을 추가하지 않는다.
- **다른 초기화와의 차이:** **[테스트용 초기화]는 화면 결과만 비우는 동작**이고, **[가상 체험 종료/새로 시작]**은 기존 결정대로 가상 세션의 검색어·결과까지 초기 상태로 돌린다. **검색 기록 자체를 삭제**하는 기능은 기록 화면의 별도 삭제 버튼과 확인 절차를 사용한다.

#### 화면 너비가 달라질 때의 배치 규칙

- **넓은 PC 화면(가로 1,200px 이상):** 왼쪽 메뉴 약 280px, 가운데 결과 카드 목록, 오른쪽 요약 패널 약 320px을 나란히 배치한다. 검색 입력·태그·버튼은 상단에서 가로로 정렬한다.
- **중간 크기 화면(가로 768~1,199px):** 왼쪽 메뉴를 축소하거나 접는 메뉴로 바꿀 수 있다. 검색 입력칸과 버튼은 필요한 만큼 줄을 바꾸며, 결과 카드와 오른쪽 요약은 겹치지 않도록 세로 배치할 수 있다.
- **스마트폰 화면(가로 767px 이하):** 상단 검색 영역을 **입력 → 태그 → [검색] → [테스트용 초기화]** 순서로 배치하고, 카드 목록과 합계 패널은 한 열로 표시한다. 메뉴는 접거나 모바일 탐색 영역으로 옮긴다. 본문은 **세로 스크롤**로 모두 볼 수 있어야 하며, 글자·버튼이 잘리거나 화면에 **가로 스크롤**이 생기지 않아야 한다.
- **모든 크기 공통:** 긴 회사명·특약명·금액은 잘리지 않게 줄바꿈하거나 적절한 공간을 확보한다. 키보드 탐색·버튼 포커스 표시를 지원하고, 손가락으로 누르는 주요 버튼은 최소 **44×44px**의 누르기 영역을 확보한다. 브라우저 확대·축소와 기기 회전 후에도 검색·상세보기·초기화·백업 기능에 접근할 수 있어야 한다.

### 2. 보험 자료 등록·관리 화면

- PDF·사진(JPG·PNG) 등의 **여러 파일을 한 번에 선택**한다. 각 파일의 미리보기를 열어 개인정보 마스킹 여부를 직접 확인한 뒤 **변환 저장 또는 필요할 때 불러오기** 방식을 선택한다.
- 마스킹은 **업로드 전에 직접 수행**하거나 **페이지 내부에서 수동 수행**할 수 있도록 한다. 내부 마스킹을 제공할 때는 화면에 검은색을 덮는 수준이 아니라 실제 저장되는 파일에서 개인정보가 제거되는지 검증해야 한다. 안전한 제거를 검증하지 못한 파일은 마스킹 완료본으로 취급하지 않는다.
- 파일마다 `질병`, `상해`, `운전자`, `여행`, `실손` 등의 태그를 **여러 개** 지정할 수 있고, 사용자 지정 태그도 추가한다. 전체 검색과 태그별 필터 검색을 모두 제공한다.
- 보험회사·상품명·특약명·계약 구분명을 이용하여 문서 연결 후보를 보여 주되, 사용자가 확인해야 실제 보험상품과 연결된다. 비슷한 이름의 문서를 자동으로 같은 계약으로 확정하지 않는다.
- 보험상품 하나에 보험증권·약관·계약서·변경된 보장내역 등 여러 문서를 연결하고, 문서 종류·날짜·버전을 보존한다.
- **글자를 선택·복사할 수 있는 PDF**는 브라우저에서 글자를 추출해 보여 주고, 사용자 확인을 거쳐 문서별·페이지별 **텍스트와 문서정보를 JSON 형태로 변환해 저장**한다. 검색은 저장된 텍스트를 대상으로 한다. 사진·스캔 PDF 등 추출할 텍스트가 없는 자료는 원본을 옆에 띄우고 직접 입력한다. 현재 버전에는 AI 기반 OCR이나 자동 의미 해석을 넣지 않는다.
- 비밀번호가 설정된 PDF는 비밀번호를 우회하거나 자동 해제하지 않는다. 필요한 보험정보를 직접 입력한다. 파일 자체의 보관 여부는 사용자가 선택할 수 있다.
- **기본 등록값:** 보험회사, 상품명, 특약명, 가입금액, 보험 상태, 가입·보장 시작일, 종료일(해당 시), 문서 연결.
- **필요할 때 추가하는 값:** 적용 질병명·진단코드 또는 코드 범위, 지급 방식(정액·회당·일당·실손 등), 지급 조건, 횟수·일수·금액 한도, 면책·감액 조건, 약관 버전, 원문 페이지·근거, 확인 메모.
- 현재 유지 중인 보험뿐 아니라 **해지·만기된 보험**도 등록하고, 진단·치료 시점과 해당 계약의 보장기간을 비교한다.

#### PDF 변환·브라우저 저장·필요할 때 불러오기

- **기본 — 브라우저에 변환해 저장:** 보험약관과 보험증권 PDF를 선택하면, 추출 가능한 텍스트를 페이지 번호·문서 종류·원본 파일명·버전·태그·보험상품 연결과 함께 JSON 데이터로 만들고 브라우저 내부의 **IndexedDB**에 보관한다. 원본 PDF 파일 전체를 기본 저장하지 않는다. 보장정보·메모·검색 기록도 연결해 저장한다.
- **미리보기:** PDF 원문은 등록 직후 미리 볼 수 있다. 이후에도 원문 화면이 필요한 경우 원본 PDF를 다시 선택해 열도록 한다. 사용자가 별도로 선택한, 개인정보 제거를 확인한 일부 페이지의 미리보기 이미지(WebP 또는 PNG)는 선택 저장할 수 있다. 이미지가 있다고 글자 검색이 가능하다고 표시하지 않는다.
- **대용량 — 필요할 때 불러오기:** 변환 후 예상 저장량이 현재 브라우저의 사용 가능한 공간보다 크거나 저장에 실패하면, **[원본 PDF는 기기에 보관하고 필요할 때 불러오기]**를 제안한다. 용량 확인 기능이 지원되지 않는 브라우저에서는 저장을 시도하기 전 사용자가 이 방식을 직접 선택할 수 있다. 이 경우 파일의 이름·종류·크기·버전·연결 관계만 보관하고, 본문을 열거나 검색할 때 사용자가 **[PDF 불러오기]**로 파일을 다시 선택한다. 저장을 강제하거나 자료를 임의 삭제하지 않는다.
- **불러오기 상태 구분:** 텍스트를 이미 변환 저장했다면 원본 PDF가 없어도 **텍스트 검색은 가능**하지만 원문 대조에는 PDF 재선택이 필요하다. 텍스트 자체를 저장하지 않은 대용량 문서는 파일을 다시 불러오기 전에는 **본문 검색에서 제외**하고 화면에 **미불러옴/이번 검색에서 제외**라고 명확히 표시한다. 불러온 뒤에는 **[이번에만 사용] / [변환 데이터 저장]**을 선택할 수 있다.
- **원본 및 개인정보 보호:** 원본 PDF는 사용자 기기에 그대로 두며 HTML이 원본을 이동·삭제·덮어쓰지 않는다. 브라우저에 보관하는 텍스트·미리보기·직접 입력 내용에도 개인정보가 남지 않았는지 저장 전 확인한다. 마스킹하지 않은 PDF 원본을 브라우저에 자동 보관하지 않는다. 검증된 마스킹 PDF의 **원본 파일 자체를 보관**하려면 사용자가 별도로 선택해야 한다.
- **파일 다시 연결:** 브라우저는 외부 PDF의 파일 경로를 자동으로 계속 읽을 수 있다고 가정하지 않는다. 파일명·크기·문서 연결 정보를 보여 주어 사용자가 올바른 파일을 다시 선택하도록 하고, 기존 약관·증권의 문서ID·버전·페이지 근거는 유지한다.

### 3. 질병·상해 검색 화면

1. 질병명·상해명 또는 진단코드 **한 개**를 입력한다.
2. HTML에 포함된 **기본 진단코드·질병명 목록**에서 코드 또는 이름의 후보를 보여 준다. 사용자가 동의어·비슷한 표기·코드 연결을 추가·수정하거나 파일로 갱신할 수 있다. 이 검색은 등록된 표기·사전·문자열 규칙을 사용하는 일반 검색이며 AI 검색이 아니다.
3. 사용자가 검색 범위를 전체 문서 또는 선택한 태그로 좁힐 수 있다.
4. 관련 문구가 있는 **약관부터 검색**하고, 원본 파일명·페이지/위치(확인 가능한 경우)·해당 문구 및 적용 조건을 보여 준다.
5. 약관의 항목을 실제 **보험증권에 기재된 가입 상품·특약**과 크로스체크한다. 이어 계약 기간, 진단·치료일, 지급 횟수·간격·한도·면책·감액 조건을 확인한다.
6. 약관 버전이 여럿이면 계약·진단 시점과 적용기간을 비교하고 **사용자가 적용 버전을 확인**한다.
7. 약관과 보험증권이 서로 맞지 않거나 특약 가입 여부가 불명확하면 **불일치/추가 확인**으로 표시하고, 확인 전에는 지급가능금액 합계에 넣지 않는다.
8. 관련성이 의심되는 다른 특약도 후보로 보여 주되, 명칭이 비슷하다는 이유만으로 지급 가능하다고 확정하지 않는다.
9. 저장된 JSON 텍스트를 검색 대상으로 삼되, **불러오지 않아 검색에서 빠진 대용량 PDF의 이름과 개수**를 결과에 함께 표시한다. 일부 문서가 빠진 결과를 전체 약관의 검색 완료로 표현하지 않는다.

### 4. 지급 조건 확인 화면

- 한 번에 모든 의료정보를 요구하지 않고, 검색된 특약에 **필요한 질문을 순서대로** 보여 준다.
- 예: 진단확정 여부·진단일·수술 여부·수술일·입원일수·통원/진료비·과거 지급 여부와 같은 항목을 해당 보장의 조건에 따라 확인한다.
- 각 조건에서 **[예] [아니요] [모름]**을 선택하고, 메모와 원본 서류의 근거를 연결할 수 있다.
- 사용자 본인이 지급 조건을 검토한 뒤 **최종 확인**해야 지급가능금액 분류에 반영한다. 확인하지 않은 조건은 자동으로 `예`로 처리하지 않는다.
- 같은 특약의 최초 1회·회당·일당 지급, 지급 횟수·기간·금액 한도, 등록된 면책·감액 규칙을 적용한다. 계산식·조건이 부족하면 **계산 불가/추가 확인 필요**로 표시한다.
- 계산 가능한 항목에는 **입력한 가입금액, 적용 횟수·일수·한도·감액, 실제 적용한 계산식, 원 단위 결과**를 함께 보여 사용자가 손계산과 대조할 수 있게 한다. 필요한 사실이나 약관 조건이 없는 경우 정확한 금액인 것처럼 숫자를 표시하지 않는다.
- 사용자는 항목별 **미청구 / 청구함 / 모름**을 표시할 수 있다. 지급액·지급일·심사 상태를 포함한 상세 지급 이력 관리는 추후 기능이다.
- 체크·메모·확인 날짜·계산 결과·수정 이력을 저장한다.

### 5. 검색 결과 및 합계 화면

| 결과 구분 | 표시 기준 | 합계 처리 |
| --- | --- | --- |
| **지급가능금액** | 등록된 자료에서 관련 조건을 확인하고 사용자가 최종 체크한 항목의 **조건 충족 추정액** | 확인된 계산 가능한 항목만 합산 |
| **예상금액** | 관련 보장 후보이며 금액 추정은 가능하지만 지급 조건의 일부 확인이 더 필요한 항목 | 지급가능금액과 **분리해** 예상 합계 표시 |
| **정보 부족·추가 확인** | 계약·특약·진단·기간·횟수·한도 등 정보 부족으로 금액을 계산할 수 없거나 자료가 불일치하는 항목 | 임의 금액을 만들지 않고 합계에서 제외 |

- 모든 항목에 보험회사·상품·특약·가입금액/계산액·적용한 조건·원문 근거·미청구 체크 상태를 표시한다.
- **지급가능 → 예상 → 정보 부족** 순서 또는 **보험회사 → 상품 → 특약** 순서로 전환할 수 있다.
- 여러 보험계약의 동일한 이름의 특약을 임의로 하나로 합치지 않는다. 반대로 같은 계약·특약·진단 사건이 중복 등록된 경우 경고하고 재확인한다. 실손은 실제 의료비·공제·중복보장 조건을 따로 검토하며 불명확한 금액은 자동 합산하지 않는다.
- **'지급가능금액'도 보험사의 확정 지급액을 뜻하지 않음**을 결과 화면에 분명하게 표시한다.
- 검색 기록을 저장·조회·삭제할 수 있고, PDF 인쇄·저장 및 엑셀에서 열 수 있는 CSV 다운로드를 제공한다. 내보낼 때 질병명·진단코드·진단일 등 민감정보의 포함 여부를 선택한다.

### 6. 자동 저장·백업·복원 및 변경 보호

- 사용자가 입력·수정한 자료 및 변환한 약관·증권의 **페이지별 텍스트(JSON)**는 지원되는 브라우저의 **IndexedDB**에 자동 저장한다. 저장 전후 사용량·오류를 확인하고, 성공/실패 여부를 사용자에게 알린다. 중요한 변경 후 **백업할지 안내**하며 마지막 백업 날짜를 기록한다. 저장 공간이 부족하거나 IndexedDB가 동작하지 않으면 불러오기·백업 파일 중심으로 전환하도록 안내한다.
- **일반 창:** 해당 기기의 해당 브라우저·프로필에서 저장 성공한 기록은 HTML을 닫았다 다시 열어도 불러오도록 한다. 저장 상태를 **저장 중/저장 완료/저장 실패**로 표시하고, 닫을 때 한꺼번에 저장하는 방식에만 의존하지 않는다.
- **시크릿/개인정보 보호 창:** HTML 열기, 약관 검색, 조건 입력, 금액 계산, PDF 불러오기, 파일 백업·복원이 가능하도록 한다. 브라우저 저장이 차단되면 **현재 열린 창에서만 사용하는 임시 데이터**로 동작하고, **[창을 닫으면 기록이 사라질 수 있습니다. 계속 사용하려면 백업 파일을 저장하세요]**라고 안내한다. 시크릿 창의 저장 기록이 창 종료 후 유지된다고 약속하거나 일반 창의 기록을 자동 불러오지 않는다.
- **브라우저·기기 변경:** LG그램의 엣지와 아이맥의 사파리·크롬 등은 저장 공간을 공유하지 않는다. 새 브라우저에서는 **백업 파일을 직접 선택해 복원**하며, 양쪽에서 따로 변경한 내용은 자동 동기화되지 않는다.
- **가상 테스트 파일 저장·불러오기:** 체험 중 **[가상 테스트 저장]**을 누르면 가상 보험상품·약관 텍스트·가입금액·태그·검색어·조건 체크·계산 결과·문서 연결 정보를 **`가상테스트_날짜_이름.json`**으로 다운로드한다. **[가상 테스트 불러오기]**로 이 JSON 파일을 선택하면 저장 당시 가상 상태를 체험 모드에 복원한다. 현재 가상 상태를 교체하기 전에는 확인한다. 가상 파일은 실제 보험 기록으로 자동 병합하지 않는다.
- **읽기용 문서:** 필요하면 같은 체험 자료의 가상 약관·증권·계산 결과를 **PDF 문서로 출력·저장**할 수 있다. PDF는 읽거나 PDF 등록을 시험하는 문서이며, **검색·체크·계산 상태까지 다시 불러오는 파일은 JSON**이라고 명확하게 안내한다.
- **체험 종료·기록 분리:** 체험 모드는 자동 저장하지 않으며 종료하거나 다시 열면 초기 검색 상태로 돌아간다. 사용자가 내려받은 JSON/PDF 파일은 기기에 남아 다음 체험에서 직접 다시 불러올 수 있다. 실제 자료의 자동 저장·일반/전체 백업에는 가상 체험 기록을 섞지 않는다.
- **일반 백업:** 보험정보·태그·문서 연결·페이지별 변환 텍스트·검색·체크·계산·수정 기록 등 **구조화된 JSON 정보**를 포함한다.
- **전체 백업:** 일반 백업에 브라우저에 실제로 보관한 **마스킹 확인 완료 미리보기 이미지 및 사용자가 보관을 선택한 마스킹 PDF**를 추가한다. **필요할 때 불러오기 방식의 외부 원본 PDF는 자동 포함되지 않으므로**, 전체 백업에도 파일명·버전 등 재연결 목록을 표시하고 복원 후 재선택을 요청한다.
- 두 백업 모두 현재 버전에서는 **암호화하지 않는다.** 개인정보가 포함될 수 있음을 저장 전에 경고한다.
- 복원 시 내용을 먼저 보여 주고 **[기존 자료와 합치기] / [전체 교체]** 중 선택한다. 합칠 때 같은 항목의 내용이 다르면 항목별 차이를 보여 주고 유지·교체를 직접 선택한다. 교체 전 기존 자료 백업을 권고한다. 외부 원본 PDF가 빠진 경우 **재연결 필요**로 표시해 정보·텍스트와 원본 파일의 관계를 잃지 않도록 한다.
- 삭제 전 확인창, 실수한 변경을 되돌리는 기능, 등록된 마스킹 원본 문서의 보호를 제공한다. 삭제는 사용자가 명시적으로 선택해야 한다.
- 컴퓨터와 스마트폰의 기록은 서버로 자동 동기화하지 않는다. 기기 간 이동은 백업 파일을 직접 전달해 복원하고, **백업에 없는 외부 PDF는 해당 기기에서 직접 다시 선택**한다. HTML 파일을 옮기거나 이름을 바꾸는 것만으로 브라우저 저장소까지 따라간다고 보장하지 않는다.

### 이번 버전의 필수 기능 요약

1. HTML 파일 한 개로 오프라인 실행 및 컴퓨터·아이폰·안드로이드용 반응형 화면.
2. 마스킹한 보험·병원 문서의 다중 등록, 미리보기·태그·상품 연결·버전 보관, **파일별 변환 저장/필요 시 불러오기 선택**.
3. PDF의 선택 가능한 글자를 **페이지별 JSON으로 변환·검색**하고 수동 보장정보 등록·수정; 암호 PDF 및 스캔 자료 수동 입력.
4. 오프라인 질병명·진단코드 사전, 일반 문자열 검색, 약관 → 보험증권 → 조건 순서의 교차 확인.
5. 조건별 체크폼과 근거·메모, 지급가능·예상·정보 부족 구분 및 계약별 중복 확인.
6. **일반 창의 IndexedDB 자동 저장, 시크릿 창의 임시 사용·백업 안내**, 가상 테스트의 별도 JSON 저장·불러오기와 선택 PDF 출력, 대용량 PDF 재불러오기, 일반/전체 백업, 브라우저 간 수동 복원, 삭제 확인·되돌리기, 검색 이력.
7. 원본 근거를 포함한 검색 결과의 PDF·CSV 내보내기.

- 보험사·상품·특약은 **서로 다른 계약을 구분할 수 있는 내부 식별자**로 관리한다. 주민등록번호나 전체 계약번호를 강제로 요구하지 않는다.
- 사진·글·문서·코드 사전·오픈소스 코드를 이용할 때는 **출처와 사용·재배포 가능 여부**를 별도로 확인한다. 외부 네트워크 연결을 전제로 하는 라이브러리는 사용하지 않으며 필요한 코드와 자료는 HTML 하나에 포함한다.
- 테스트를 위해 가상의 체험 자료를 제공하되 실제 사용자 자료와 섞거나 브라우저에 자동 저장하지 않는다. 사용자가 직접 선택하면 **가상 자료와 검색·계산 상태를 JSON 문서로 내보내고 다시 불러올 수 있다.** 가상 약관·증권·계산 결과의 읽기용 PDF도 별도 저장할 수 있다.

## 완료 기준

아래 체크박스는 **제작 후 실제 시험할 항목**이다. 기획 단계에서 미리 완료 표시하지 않는다.

- [ ] **01. 단일 파일·시크릿 창:** HTML 파일 한 개만으로 컴퓨터·아이폰·안드로이드의 일반 창과 시크릿/개인정보 보호 창에서 열리며, 로그인·API 키·서버·챗봇·AI 호출 없이 검색·금액 계산이 실행된다. 네트워크를 끊은 상태에서도 확인한다.
- [ ] **02. 첫 화면·체험 파일:** 처음에는 실제 보험 기록이 비어 있고, 별도 체험 버튼을 눌러야 가상의 자료를 볼 수 있다. 체험 검색·계산 상태를 **JSON 문서로 저장했다가 다시 불러오면 동일 상태로 복원**된다. 체험 종료·재시작 시에는 초기 검색 상태로 돌아가며 실제 기록에 남지 않는다.
- [ ] **03. 다중 등록:** PDF·사진 여러 개를 선택하면 파일별 미리보기, 마스킹 확인, 여러 태그 지정, 보험상품 연결 후보와 최종 확인, **변환 저장/필요 시 불러오기 선택**이 가능하다.
- [ ] **04. 마스킹 안전성:** 저장한 JSON 텍스트·미리보기·선택 보관한 마스킹 PDF에서 가린 민감정보가 다시 노출되지 않는지 확인한다. 안전성을 입증하지 못한 경우 완료로 처리하지 않는다.
- [ ] **05. 파일 추출·수동 입력:** 글자를 선택할 수 있는 PDF를 등록하면 **페이지별 텍스트 JSON이 생성·검색**되고 페이지 근거가 유지된다. 스캔·사진·암호 PDF는 강제 인식·해제 없이 원본을 참고해 직접 입력할 수 있다.
- [ ] **06. 보험상품 연결:** 보험증권과 약관을 특정 상품·계약에 연결하고 서로 다른 계약이나 문서 버전을 구분할 수 있다.
- [ ] **07. 태그 검색:** `질병`·`상해`·`운전자`·`여행`·`실손` 및 직접 만든 태그를 여러 개 지정하고 전체/태그 필터를 전환하면 검색 범위가 바뀐다.
- [ ] **08. 진단코드 검색:** 질병명 또는 진단코드 한 개를 입력하면 오프라인 코드 목록에서 관련 이름/코드 후보를 보여 주고, 사용자가 직접 추가·수정한 연결을 검색에 반영한다.
- [ ] **09. 검색 순서:** 약관의 관련 항목을 먼저 찾고 보험증권의 실제 특약 가입 여부를 확인한 후 지급 조건을 단계적으로 보여 준다.
- [ ] **10. 날짜·버전:** 진단·수술·입원 날짜와 현재/과거 보험의 보장기간, 해당 약관 버전을 비교하고 사용자가 적용 여부를 확인할 수 있다.
- [ ] **11. 불일치:** 약관에 있는 보장이 증권과 불일치하거나 특약 가입이 불명확하면 확인 필요로 표시하고 지급가능금액 합계에 자동 포함하지 않는다.
- [ ] **12. 체크폼:** 필요한 지급 조건에만 예/아니요/모름 선택, 메모, 근거 연결이 나타나며, 모름이나 미확인 값을 자동으로 예로 취급하지 않는다.
- [ ] **13. 정액 계산:** 개인정보 없이 준비한 가입금액·조건을 입력했을 때 정액·회당·일당 계산액과 표시된 계산식·원 단위 결과가 손계산과 같다.
- [ ] **14. 한도·조건:** 최초 1회·횟수·일수·한도·등록된 면책·감액 조건을 적용하고, 필요한 규칙이 빠진 경우 임의 금액 대신 계산 불가/추가 확인으로 표시한다.
- [ ] **15. 실손 구분:** 실손 의료비 계산에 실제 의료비·적용 규칙 등이 부족하면 확정처럼 합산하지 않는다.
- [ ] **16. 합계 분리:** 지급가능금액과 예상금액의 항목별 금액·각각의 합계를 따로 보여 주고, 정보 부족 항목을 합계에서 제외한다.
- [ ] **17. 상품 표시:** 각 금액에 보험회사·상품명·특약명·근거 문서가 연결되어 있고 정렬 방식을 전환할 수 있다.
- [ ] **18. 중복 검사:** 서로 다른 계약의 보장은 구분하고, 같은 계약·특약·사건의 중복 등록에는 경고를 표시한다.
- [ ] **19. 청구 여부:** 사용자가 미청구/청구함/모름을 선택하고 상태별로 확인할 수 있지만, 지급 이력이나 청구 결과를 자동으로 만들어 내지 않는다.
- [ ] **20. 이력·원본:** 검색·조건 체크·계산·수정 이력을 저장하고, 수정·삭제 확인 및 되돌리기 후에도 의도치 않게 원본이 사라지지 않는다.
- [ ] **21. 저장·재불러오기:** 일반 창에서 저장한 텍스트와 입력 기록은 같은 브라우저·프로필에서 다시 열어 검색된다. 시크릿 창에서는 저장소가 차단되어도 임시 검색·금액 계산이 가능하고 종료 시 기록 소실 및 백업 안내가 나타난다. 큰 PDF는 미불러옴/검색 제외 표시 후 재선택하여 검색할 수 있다.
- [ ] **22. 백업·복원:** 실제 자료의 일반 백업에 **변환 텍스트와 구조화 기록**, 전체 백업에 **실제 보관 중인 마스킹 이미지/선택 보관 PDF**가 포함된다. 외부 PDF 누락 목록·재연결 안내, 복원 전 미리보기·합치기/교체·충돌 선택이 동작하고 복원 후 금액과 기록이 원본과 같다. **가상 테스트 파일은 실제 백업과 혼합되지 않는다.**
- [ ] **23. 내보내기:** 결과의 PDF 및 CSV 파일을 저장할 수 있고, 민감정보 포함 여부에 따라 출력 내용이 실제로 달라진다.
- [ ] **24. 모바일:** LG그램에서 사용하는 브라우저, 아이맥에서 사용하는 브라우저, 아이폰·안드로이드의 일반/시크릿 창에서 주요 입력·검색·계산·백업·복원 버튼을 사용하고 좁은 화면에서 중요한 정보가 겹치거나 잘리지 않는다.
- [ ] **25. 검증:** 개인정보를 제외한 약관·보장 조건·수기 계산표로 정상 검색, 불일치, 정보 부족, 중복, 계산액 대조, 일반 창 저장·복원, 시크릿 창 임시 사용, **가상 JSON 저장·불러오기 및 PDF 출력**을 검증한 뒤에만 완료 표시한다.

## 추가 기능

현재 버전과 구분하여 **나중에 구현할 기능**이다. 현재 HTML은 아래 기능 없이도 사용할 수 있어야 한다.

1. 계정 로그인·회원 관리·로컬 잠금(PIN 포함), 저장 자료·백업 파일 암호화.
2. AI 기반 약관 의미 검색·AI 챗봇·AI 문서 분석, 사진·스캔의 고급 자동 OCR. 현재 버전은 일반 문자열 검색과 수동 확인만 사용한다.
3. 보험회사 외부 시스템의 API 연동, 실시간 계약·청구 내역 조회, 기기 간 서버 자동 동기화.
4. 상세 보험금 지급 내역(지급일·수령액·부분 지급·거절) 관리, 청구 준비서류·청구 진행 상태·접수 연결 및 기한 알림.
5. HTML의 CSS·JavaScript·자료 사전을 여러 파일로 분리하는 확장형 구조. **현재는 한 파일**로 유지한다.

## 한계 및 비목표

1. **보험금 지급 판단의 한계:** 질병명·진단코드 일치만으로 보험금 지급이 확정되지 않는다. 표시 금액은 사용자가 등록하고 확인한 약관·증권·진단·치료 조건에 따른 추정치이며, 보험사 심사·해석·지급 결정이나 법률·의료 판단을 대신하지 않는다. 청구 여부도 사용자가 표시한 상태를 기준으로 한다.
2. **문서 해석·마스킹의 한계:** 로그인·API·서버·AI·자동 암호 해제는 현재 사용하지 않는다. 선택 가능한 글자가 없는 사진·스캔 PDF와 읽을 수 없는 암호 PDF는 직접 입력한다. 페이지 안의 마스킹은 개인정보가 실제 제거된다는 검증이 필수이며, 검증되지 않은 시각적 가림을 안전한 마스킹으로 표시하지 않는다.
3. **단일 HTML·브라우저 저장의 한계:** 브라우저·기기마다 `file://`로 연 HTML의 저장 권한, IndexedDB의 용량·유지, 인쇄·PDF 기능이 달라질 수 있고 자료가 자동으로 다른 기기에 전송되지 않는다. **시크릿 창의 기록은 종료 후 삭제되거나 저장 자체가 차단될 수 있으며**, 실제 자료를 이어 쓰려면 저장한 백업 파일을 다시 불러와야 한다. **JSON으로 변환해도 표·그림·서식·법적 효력이 원본 PDF와 같아지는 것은 아니며**, 정확한 조항 확인에는 원본 PDF 재불러오기가 필요할 수 있다. 텍스트가 없는 스캔 PDF는 자동 검색되지 않는다. 이번 버전은 개인정보를 입력하지 않지만 현재 저장소와 백업은 **암호화하지 않으므로** 실제 개인정보를 임의 입력하거나 포함된 PDF를 보관하지 않도록 주의한다. 실제 브라우저에서 저장·복원·마스킹·모바일 동작을 확인하지 못하면 해당 기능을 완료로 간주하지 않는다.

## 검증 방법

**검증 방식 1가지 — 개인정보를 가린 실제 문서와 수기 계산 결과를 기준으로 한 통합 대조 검증**

1. 개인정보를 제거한 실제 보험증권·약관·진단/치료 자료를 준비한다. 등록할 보험상품·특약·문서 버전을 사람이 먼저 대조해 정답표를 만든다.
2. 정답표에 진단코드, 해당 약관 조항·페이지, 실제 가입 특약, 적용 기간, 지급 방식·횟수·한도·감액, 체크 조건, 예상 합계의 **손계산 과정**을 적는다.
3. 같은 문서를 HTML에 등록하여 PDF → **페이지별 JSON 변환 내용 및 페이지 번호**를 원본과 비교한 뒤, 약관 검색 → 증권 대조 → 날짜·횟수·특약 확인 → 예/아니요/모름 체크 → 금액 계산을 수행한다.
4. 페이지의 각 결과를 **정답표의 원문·특약·계산식·수기 합계**와 항목별로 비교한다. 일치하지 않으면 입력 오류인지 코드·계산 로직 오류인지 기록하고 수정 후 같은 조건을 재시험한다.
5. 일부 자료를 의도적으로 누락하거나 불일치·중복 기록을 추가해, 결과가 지급가능금액에 잘못 더해지지 않는지 확인한다.
6. **작은 PDF의 변환 저장**과 **큰 PDF의 필요 시 불러오기**를 각각 실행하고, 불러오지 않은 문서가 검색에서 제외됐다고 표시되는지 확인한다. 변경·삭제·되돌리기, 일반/전체 백업·복원(합치기·교체·충돌 선택), PDF·CSV 내보내기를 같은 기록으로 검증한다. 복원 전후 건수·태그·문서 연결·변환 텍스트·금액 합계를 비교하고 외부 PDF의 재연결 안내도 확인한다.
7. 인터넷을 끄고 LG그램·아이맥·아이폰·안드로이드의 일반 창과 시크릿 창에서 직접 열어 검색·금액 계산을 확인한다. 일반 창에서는 닫았다 다시 열었을 때 변환 데이터가 남는지, 시크릿 창에서는 임시 사용과 파일 다운로드·복원이 가능한지 확인한다. **가상 검색·계산을 JSON으로 저장하고 새 체험에서 다시 불러온 뒤 값·체크·검색 결과를 대조**하며, PDF 문서 출력과 실제 기록 분리도 확인한다. 미리보기/JSON/백업에서 가린 민감정보가 다시 드러나는지도 검증한다.
8. 첫 화면에서 검색을 실행한 다음 **[테스트용 초기화]**를 눌러 **결과 카드·건수·현재 계산 합계·그래프만 사라지는지** 확인한다. 검색어·태그·보험 자료·검색 기록·체크·메모는 그대로인지 확인하고 **[검색]**을 다시 눌러 이전과 같은 결과를 얻는지 비교한다. PC 창의 크기를 바꾸거나 스마트폰으로 열어 버튼이 가려지지 않는지도 확인한다.

> **기록 원칙:** 실제로 실행하지 않은 시험에는 완료 표시를 하지 않는다. 브라우저나 단일 HTML 제약으로 실패한 항목은 실패 또는 미확인으로 기록하고, 임의로 성공 처리하지 않는다.

### 저장 방식 설계 참고 자료

- [MDN — IndexedDB API](https://developer.mozilla.org/ko/docs/Web/API/IndexedDB_API): 페이지별 텍스트·문서정보와 대용량 구조화 데이터의 브라우저 저장 방식.
- [MDN — 브라우저 저장 공간 및 삭제 조건](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria): 저장 용량·브라우저의 자동 삭제 가능성·백업이 필요한 이유.
- [MDN — File API](https://developer.mozilla.org/en-US/docs/Web/API/File_API/Using_files_from_web_applications): 사용자가 PDF를 직접 선택해 불러오는 방식.
- [MDN — 로컬 파일의 출처 제한](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy#file_origins): `file://` HTML 저장·접근 동작을 브라우저별로 확인해야 하는 이유.
- [Mozilla PDF.js](https://mozilla.github.io/pdf.js/getting_started/): PDF 표시·텍스트 추출 구현에 참고할 수 있는 공식 문서. 단일 HTML·오프라인 사용 가능 여부는 실제 구현과 기기별 시험으로 확인해야 한다.
- [MDN — 비공개 창에서의 웹 저장](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API): 시크릿/개인정보 보호 창은 데이터 저장이 임시적일 수 있음을 확인하는 자료.
- [Microsoft — Edge InPrivate](https://support.microsoft.com/ko-kr/edge/browse-inprivate-in-microsoft-edge): 엣지 비공개 창의 데이터 보존 범위를 확인하는 공식 자료.

### 앞선 질문에서 추가로 확정한 세부 요구

- 보험증권·약관 업로드와 보장정보 직접 입력을 모두 지원한다.
- 진단명·진단코드 검색 이후 실제 진단·치료 정보를 직접 입력하거나 관련 서류를 참고해 확인한다.
- 약관 원문·지급 조건·출처를 결과와 연결하고, 지급가능금액과 예상금액을 구분해 보험회사·상품별로 보여 준다.
- 진단코드/질병명의 양방향 검색과 유사한 **표기**의 추천은 내장 사전 및 일반 문자열 규칙으로 처리한다. AI 검색은 나중에 추가한다.
- 현재 보험과 과거 해지·만기된 보험도 함께 등록해 사고 시점·보장기간을 비교한다.
- 보험금 청구 준비부터 진행 상태를 관리하는 기능은 나중에 추가한다. 지금은 간단한 미청구/청구함/모름 표시만 사용한다.
- 암호가 걸린 PDF의 내용은 직접 입력한다. 파일 보관 여부는 선택하되 비밀번호 해제 기능은 구현하지 않는다.
- **저장 방식 변경(2026-11-07):** 보험약관·증권 PDF는 글자를 추출해 페이지별 JSON으로 IndexedDB에 저장하는 것을 기본으로 하고, 용량 초과 또는 사용자 선택 시 원본 PDF를 필요할 때 다시 불러온다. 외부 원본을 불러오지 않은 검색은 누락 여부를 표시하며, 원본 PDF는 자동 수정·삭제하지 않는다.
- **일반/시크릿 창 및 계산 검증 변경(2026-11-08):** 개인정보 없이 가입금액·특약 조건·필요한 사건 정보를 입력해 계산식과 원 단위 추정액을 확인한다. 시크릿 창에서도 검색·계산이 가능하도록 하되 저장 기록의 영구 보존은 약속하지 않는다. 브라우저별 실제 기록은 분리되며 백업·복원으로 이동한다. 체험 모드는 언제나 초기 검색 상태로 돌아가고 실제 기록을 건드리지 않는다.
- **가상 문서 저장·복원 추가(2026-11-08):** 체험 모드에서 만든 가상 보험자료·검색·계산·체크 상태를 JSON 문서로 저장하고 다시 불러올 수 있다. 가상 약관·증권·계산 결과를 읽기용 PDF로 저장하는 기능도 제공한다. 체험은 여전히 자동 저장하지 않고, 실제 보험 기록과 분리한다.
- **첫 화면 디자인 확정·테스트용 초기화 추가(2026-11-08):** 첫 번째 PC 시안의 민트 배경·청록색 세로 메뉴와 합계 패널·흰색 검색/결과 카드·머스터드 검색 버튼을 기준으로 한다. **[테스트용 초기화]**는 현재 표시된 검색 결과와 해당 합계만 지우며, 검색어·태그·원본 문서·변환 텍스트·검색/변경 기록·가상 파일은 유지한다. 좁은 창에서는 입력·카드·합계를 세로로 재배치한다.
